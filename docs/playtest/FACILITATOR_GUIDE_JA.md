# QUANT RUSH v3.1 プレイテスト 進行役ガイド

このテストは、**初見の人が説明なしで「操作・目的・RISK と HEDGE・制限時間」を理解できるか**を確かめるためのものです。
これまでの数値（`docs/BALANCE_V3.md`）はコンピューターのモデルによる推定で、人間のプレイテストの代わりにはなりません。
このテストの記録が、初めての実データになります。

## 大原則
- **回答や結果を作らない・補わない。** 聞いた言葉と見た行動だけを書く。空欄は空欄のまま残す。
- プレイ中は説明・ヒントを出さない。質問されたら「どう思いますか？」と返す。
- 個人情報（名前・連絡先・顔写真）は記録しない。参加者は P01, P02… の ID で管理する。
- 画面録画や音声録音をするときは、事前に本人の同意を取る。
- テスト中はルール・数値を変えない（全員が同じビルドで遊ぶ）。

## 準備（参加者ごと）
1. ビルドを決めて、チェックシートにコミットを書く。
   - v3.1 + Phase 3：`feature/v3-intuitive` @ `fc5fc00`。以降のコミットはドキュメントのみ。
2. 遊ぶ場所を用意する。次のどちらか。
   - ローカル：`npm run build` → `npx vite preview --host` を実行し、同じ Wi-Fi のスマホから `http://<PCのIP>:4173` を開く。
   - Cloudflare Pages のブランチプレビュー：`https://feature-v3-intuitive.quant-rush-4ws.pages.dev` の想定。開発環境からは未確認なので、事前に開けるか確かめる。
3. **初見の状態にする。** シークレット / プライベートウィンドウで開く。
   - 理由：チュートリアルは初回だけ表示され、設定は端末に保存されるため。
4. 比較しやすいようにコースを揃える（任意）。タイトルの SETTINGS で次を設定する。
   - SEED を `424242` にする。
   - FPS 表示を OFF にする（初期状態は ON。性能を記録したいときだけ ON）。
   - 音は ON。
5. スマホは画面の明るさを上げ、通知をオフにし、縦持ちで始める（横持ちは別項目として確認）。

## 期待する理解（評価の目安。参加者には見せない）
| 質問 | ◯（理解できている）の目安 | よくある誤解の例（× の目安） |
|---|---|---|
| Q1 目的（5秒） | 走るゲームで、何かを稼ぐ・金融（取引）っぽいことをする | ただのレースだと思っている。何も読み取れない |
| Q2 操作 | 左右でレーン移動、上でジャンプ、HEDGE ボタン / SPACE | HEDGE の存在を知らない。ジャンプできると知らない |
| Q3 目的 | お金（PnL）やスコアを増やす。取引で稼ぐ | 速く走る・距離だけ、と思っている |
| Q4 光るレーン | おすすめ・儲かりやすいレーン。**ただし、いつも正解とは限らない** | 「必ず正解」「ただの飾り」と思っている |
| Q5 RISK | 抱えている在庫（ポジション）の危なさ。100% で強制決済（ペナルティ）。ゲートは 60% 未満で通過 | 体力やスピードのゲージだと思っている |
| Q6 HEDGE | RISK をゼロに戻す（在庫を決済する）。コストがかかる。HEDGE! が出たら（70% 以上）押すとボーナス | 攻撃・ブーストだと思っている。押すタイミングが分からない |
| Q7 時間 | 上部のバー内の数字が残り時間。ゲートを通過すると増える。赤い斜線は時間切れになる位置 | 時間制限に気づいていない |

Q4 の補足：最初のチュートリアルの文言は「今いちばん儲かるスプレッド」です。一方、バランス調査では「平均的に有利なだけで、いつも正解ではない」と分かっています。参加者がどちらで受け取ったかを記録してください（今回は文言を変えません）。

## 観察のコツ
- 「目線」を見る：上（PnL・時間）、下（RISK）、道路（光るレーン）のどこを見ているか。
- 迷った瞬間は、時刻と、画面に何が出ていたかを書く（例：「1:40 OVERLOAD が出たが気づかず」）。
- 1回目と2回目（あれば）で行動が変わったかを書く（学習の速さ）。

## 記録のまとめ方
- 1人1枚のチェックシートを、`results-template.csv` の形式で1行にまとめる（未記入は空欄）。
- 実データは個人を特定できない形でだけリポジトリに置く。共有前に内容を確認する。
- 集計の目安（人数がそろってから）：Q1〜Q7 の ◯ の割合、HEDGE を自分から押した人の割合、RISK BURST の回数、
  ゲート失敗の回数、Q9 の分布。**少人数（例：5人）の結果は傾向の手がかりで、確定的な結論にはしない。**
